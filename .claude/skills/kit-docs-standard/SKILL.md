# The documentation standard

`kit-check-docs` holds a repository's docs to one standard: a five-section `README.md`, an index
that is the classification, reference docs that partition the source tree, numbered cookbooks,
and links that resolve on GitHub. The doctor's `docs.standard` row runs the same check wherever
`kit.docs.config.mjs` exists.

## Run it

- In the kit: `node packages/tooling/bin/kit-check-docs.mjs` (also part of `npm run check`).
- In a consumer: `npx kit-check-docs`.
- Every failure prints the file, the line where there is one, and the fix. Change the doc and the
  code it describes in the same commit.

## What each failure means

| It reports | Fix |
|---|---|
| a file under roots that no reference owns | widen the `**Owns:**` globs of the reference that explains it, write a new reference, or exempt the glob in `kit.docs.config.mjs` with a written reason |
| a file owned by more than one reference | narrow one doc's globs: one owner per file |
| an `Owns:` glob matching no file | fix the path or remove it; globs name committed source, never build output |
| a reference without an `Owns:` line | add it as the first non-blank line after the H1 |
| a composing reference linking fewer than two references | link at least two, or own files instead |
| a doc not listed in the index | add one `- [name](path) — hook` line under its class, or delete a dead note |
| a doc listed twice | keep one entry; the section it sits in is its class |
| an index entry out of alphabetical order | alphabetical by filename, case-insensitive, within its section and H3 subgroup |
| an index heading that is not a class | the H2s are Start here, Reference, Cookbook, Tutorial, Record, Postmortem, in that order |
| a docs subdirectory without a `README.md` | add one linking back to the index, one line per file |
| a link to a file that does not exist | fix the path; the check is case-exact because GitHub is |
| a link leaving the repository | link across repositories as `https://github.com/thechimaeraproject/<repo>/blob/master/<path>` |
| a place naming the version this repository currently is | write the shape (`kit-vX.Y.Z`, `^<kit version>`) and say where the real one lives: the root `package.json` |
| a place naming a version the next release can be (its next patch, minor or major) | it would pass every PR gate and stop the release: write the shape ("since the release that ships this") and record the change in `CHANGELOG.md` under `## Unreleased` |
| a cookbook step problem | H2s run `## 1. …` to `## N. How you know it worked`, in order |
| a doc without exactly one H1 | demote the others to H2, or split the file |
| `README.md` missing a required section | H2s in this order: What it is, Status, Start here, Run it, Docs |
| a postmortem numbering problem | `NNNN-slug.md`, contiguous from `0001` |

## Adding something

- **A source file** under the declared roots: extend the `**Owns:**` line of the reference that
  explains it, or exempt it with a reason. Do not leave it for the checker to find.
- **A reference:** the filename is its noun in kebab-case, and it opens like this, then has the
  sections What it owns and what the consumer supplies, one per mechanism, and Verification.
  Index it under Reference.

  ```markdown
  # Execution lanes (`kit.lanes`)
  **Owns:** `python/chimaeraproject/kit/lanes/`
  ```

- **A cookbook:** numbered H2 steps, the last `## N. How you know it worked`. Index it under
  Cookbook.
- **Any doc:** exactly one H1; in-repository links relative; cross-repository links absolute;
  an index line under its class, alphabetical.

## Habits

- A version number in backticks is still a claim: the version check reads through inline code.
  Versions below the current one are history and are fine; `CHANGELOG.md` is exempt.
- Headings and links inside fenced blocks or inline code are not scanned. A link that matters
  goes in prose.
- Windows resolves `Foo.md` for `foo.md`; GitHub does not. Match the case exactly.
- When code and doc disagree, fix one of them in the same commit. Never leave a dead note.
